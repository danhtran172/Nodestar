# SPREAD QC-001–QC-008 and D-077 Design

## Scope

Implement the nine work packages in the supplied QC implementation guide, in the required order:

1. Selection and overlay interaction.
2. Persistence and image integrity.
3. Predictive layout.
4. Seed layout.
5. V1 scope cleanup.
6. Performance verification.

The implementation must not change product semantics outside this scope. In particular, it must not change `deletionError`, the boundary-reconnection behavior of `deleteObjects`, or the treatment of ambiguous multi-selection deletion.

## Delivery strategy

Deliver one independently testable and reviewable change per work package, following WP1 through WP9. Each package must leave the application buildable and its relevant tests passing. Shared primitives may be introduced when they directly support the current package, but unrelated cleanup and speculative abstractions are excluded.

The preferred structure is to extract deterministic domain operations from the current canvas and editor components. React components retain responsibility for event wiring and rendering, while selection, snapshot choice, asset/reference commits, and layout calculations expose testable contracts.

## Selection and canvas interaction

Each object pointer-down gesture captures three distinct values:

- `clickedSelection`: the object directly under the pointer.
- `explicitSelection`: a copy of the visible selection produced by Ctrl/Meta+Click or marquee selection.
- `movementIds`: the objects that may move if the gesture crosses the drag threshold.

Ctrl/Meta+Click toggles a newly allocated set, emits it as an explicit selection, and ends the pointer-down flow without starting a drag. Clicking an object outside an explicit selection makes only that object visibly selected. For a Node, the movement set is its outgoing PATH reachability; non-Node movement contains only the clicked object. Dragging an object already inside an explicit selection copies that exact selection and suppresses downstream expansion. No set passed to React state or callbacks may later be mutated.

All interactive portal and contextual UI roots inside the canvas use `data-canvas-overlay`. Canvas pointer, double-click, wheel, and context-menu handlers ignore events whose target lies inside this boundary. Overlay capture handlers may stop propagation only when composed with caller handlers. Actions complete before any selection-clearing canvas behavior can run.

## Image request and asset integrity

Image operations carry an explicit origin (`paste`, `drop`, or `picker`) and an explicit target when available. D-077 is enforced at the paste event boundary: an image paste with more than one selected object is prevented, produces the canonical toast once, and performs no processing, busy-state transition, history write, selection change, or asset write. Direct drops and contextual pickers continue to use their explicit target.

Processed images first enter transient session state as pending previews. Canonical object image arrays are changed only after durable asset persistence succeeds. A new upload failure retains a retryable transient payload without adding an orphan reference or history entry. A failed replacement preserves the old canonical image. Retry commits exactly one reference after success; remove discards only transient state. Multi-file operations commit successful files independently.

Where IndexedDB supports the required atomic update, asset records and the map snapshot are written in one transaction spanning both stores, with asset writes preceding the map write and success reported only after transaction completion. Hydration and backup import cross-check all Node, Goal, Imagination, and imported references. Legacy missing references are removed or quarantined into an explicit non-retryable repair state; the UI must not render broken image elements or offer retry without a retained payload. Export includes only referenced durable assets.

## Persistence and recovery

Persisted maps use this envelope:

```ts
type WorkspaceSnapshot = {
  schemaVersion: 1;
  revision: number;
  savedAt: number;
  map: VisionMap;
};
```

Every persist request receives a monotonically increasing revision, including draft, undo, and redo writes. The same logical snapshot and revision are written to local recovery and IndexedDB. Queued writes cannot allow an older snapshot to overwrite a newer snapshot.

On load, local recovery and IndexedDB map candidates are read, parsed, and validated independently. The valid candidate with the highest revision wins; a legacy raw `VisionMap` is migrated in memory with the lowest priority. No candidate is written back until selection is complete. Map and asset loads use independent settled results so one store cannot erase the valid result of the other. The demo map is used only when no valid map exists.

Workspace status reports “Saved on this device” only when the durable map and asset state are healthy and the latest queued write succeeded. Recovery-only load, failed map storage, failed asset storage, or failed latest write reports a degraded state. Unmounted loads must not update React state.

## Predictive layout

A pure deterministic operation owns both ordinary branch-drag preview and semantic re-parent preview:

```ts
type PredictiveLayoutInput = {
  baseMap: VisionMap;
  movingIds: ReadonlySet<string>;
  dragDelta: Point;
  draggedRootId: string;
  targetId?: string;
  explicitSelection: boolean;
};

type PredictiveLayoutResult = {
  previewMap: VisionMap;
  valid: boolean;
  message?: string;
  relationshipChange?: RelationshipChange;
  affectedObjectIds: ReadonlySet<string>;
};
```

The operation translates the complete movement set from the immutable gesture base while preserving relative offsets. It detects collisions using complete object bounds and resolves them locally at branch level. Moving branches remain together; only adjacent colliding branches may shift, while unrelated distant objects retain exact coordinates. It does not invoke global auto-layout.

For a semantic target, cycle validation occurs before changing the one layout-attachment PATH edge. Other incoming PATH edges and all RELATED/REFERENCE edges remain unchanged. Semantic changes then pass through the same local collision pipeline. The returned preview map is the exact map committed on pointer-up. Invalid results render the message, commit nothing, and revert to the gesture base. A successful drop is one history transaction containing edge, attachment, movement, and neighbor-reflow changes.

## Seed layout

Seed placement uses a deterministic PRNG derived from the Seed `visualSeed`, Seed Box shuffle value, and current container dimensions. Placement varies horizontal position, restrained rotation, gaps, and vertical stacking with a bottom bias. It preserves semantic seed identity, text, and order.

Rotated bounds must remain collision-free and inside left, right, and bottom container bounds. Absolute rotation is capped at 35 degrees; typical short seeds target approximately 5–15 degrees in either direction, while long or tall seeds reduce rotation for readability. The algorithm supports 1, 10, 11, 20, 21, and 30 seeds in narrow and wide boxes.

Moving a Seed Box translates its current composition during the gesture. Only a successful pointer-up advances its deterministic shuffle value and settles the new composition once. Cancelled or invalid drops do not shuffle. Reduced-motion users receive the final deterministic layout without animation.

## Test and evidence strategy

Extend the Node domain suite with focused tests for immutable selection calculation, snapshot candidate ordering, independent storage failure results, durable asset/reference rules, predictive layout, and deterministic seed placement.

Add Playwright browser tests with deterministic fixtures for pointer and keyboard interaction. The regression matrix covers Normal Node, Goal, Seed Box, Imagination, selected relationships, the main Create menu, and the Map menu. Browser tests must demonstrate at minimum Details and Fit Selection actions, D-077 outcomes, drag preview/commit equality, invalid re-parent rollback, selection visibility versus movement, Seed Box settle behavior, and undo.

Failure-injection tests cover file read, image decode, thumbnail generation, asset transaction, map transaction, quota exhaustion, legacy orphan hydration, and partial batch failure. Evidence is stored by work package as Playwright screenshots, videos, traces, and machine-readable reports. Recordings required by the QC guide remain continuous within each requested scenario.

Performance fixtures contain 100, 300, and 500 Nodes plus multiple Goals, shared downstream nodes, multiple PATH relationships, RELATED/REFERENCE relationships, Seed Boxes, and Imagination thumbnails. Measurements run against the production build and record browser/version, CPU, memory, display characteristics, frame times, long tasks, React commit duration, objects and edges rerendered per pointer frame, and layout/style recalculation cost.

Optimization is evidence-driven. If profiling identifies full-map rendering as the bottleneck, apply stable identity first, memoized object/edge rendering second, visibility culling third if still needed, and animation-frame throttling only when preview remains perceptually attached to the pointer.
